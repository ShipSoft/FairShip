Changelog

All notable changes to this project will be documented in this file.

The format is based on Keep a Changelog, and this project adheres to Calendar Versioning (year.month), with the possibility of patch releases (year.month.patch).

Until April 2024 (inclusive) no changelog was kept. We might try to reconstruct it in future.

Unreleased

Added

  • Add EventHistogram (C++, libShipData) and python/event_histogram.py for histograms with event-level uncertainties in weighted samples whose entries are correlated within an event, such as the kaon/pion clones of --kaon-pion-splits. The weights of an event are summed per bin first and the per-event sums are treated as the observations; sqrt(sum w^2) over hits treats the clones of one decay as independent and can underestimate the error several-fold. Both versions also give the bin covariance, Poisson bootstrap replicas seeded by run and event number, and the effective number of independent events per bin, and write the same hadd-mergeable objects. examples/split_weight_uncertainties.py applies them to the muon spectrum at a scoring plane; examples/split_weight_uncertainties_rdf.py does the same with RDataFrame and the C++ class, also multithreaded.
  • Add a muon DIS workflow in newMuonDIS/ (see its README): prepareEvents.py follows each input muon through the material, anchored on its UBT, SBT, SST and TD hits (backwards from the UBT hit when there is one, otherwise transported through the shield field map from its start), and generates Pythia6 DIS interactions separately in each material category, with weight wDIS = muon weight × ∫ρ dl / number generated; filterEvents.py keeps the interactions whose products can reach the detector; run_simScript.py --NewMuDIS replays them, and python/MuDISGenerator_postProcessing.py then restores the incoming muon's hits upstream of each vertex, checking that every simulated event matches the interaction it was generated from. Each simulated event carries muDIS_material, muDIS_muEntry, muDIS_disIndex, muDIS_pPythia and muDIS_nGenerated; muDIS_xsec is a placeholder (-1) until a reliable cross section is available. For --NewMuDIS, -i and -n count input muons, not events. Prepared files from earlier development versions of this workflow cannot be read. The legacy --MuDIS generator is unchanged.
  • Add rootUtils.get_particle and rootUtils.is_known_particle for TDatabasePDG lookups. get_particle returns the particle for a PDG code or name and raises ValueError if it is unknown; is_known_particle returns a bool. They replace testing the result of TDatabasePDG::GetParticle directly, which returns a null pointer for an unknown code: PyROOT gives it as an object that is falsy but not None, so is None and is not None checks never fire.
  • Document building on lxplus with the pixi build on CVMFS and the pixi cvmfs extension, which keeps the environment out of the user's AFS area (#1453).
  • Add -g/--geofile to run_simScript.py to transport particles through the geometry stored in a geometry file from an earlier run, e.g. to simulate every sample of a production on one standard geometry. The geometry configuration (ShipGeo) is read from the file, so the geometry options (-Y, --strawDesign, --shieldName, --helium/--vacuums, --SND/--noSND, --SND_design, --target-yaml) are rejected with it. The modules still build their geometry from that configuration, as building is also how detectors register their sensitive volumes and magnets attach their fields, neither of which a geometry file keeps; a last module (geometry_from_file.py, on pyFairModule) then replaces the built geometry by the stored one before Geant4 converts it, copying the fields attached to volumes. It needs no new C++. The run stops if the stored geometry lacks a volume or placement that the current code builds (sensitive volumes are found by name, detector IDs come from node names and copy numbers), if the strawtube, MTC or silicon target YAML no longer gives the configuration stored with the geometry (the veto and emulsion target YAML are not stored and so cannot be checked), or if the swap did not happen. Any geometry file written by run_simScript.py can be used. A geometry file written by such a run keeps the FairShip version that built the geometry as geometryBuiltWithFairShip in ShipGeo. A new CI job (pixi run ci-geofile-loading, .github/scripts/test_geofile_loading.py) builds two different geometries, simulates again on each with -g and checks that every hit and the written geometry are the same, that the field of the MTC iron is copied, that particles go through the stored geometry (a station moved in the file changes the hits), and that invalid uses of -g are refused.
  • --store-all-tracks in run_fixedTarget.py keeps every track and every event in the output, instead of only tracks with hits in a sensitive plane (and their ancestors) in events with such hits. It is meant for validating the kaon/pion splitting at the level of the decays themselves, which needs all split clones and all kaons and pions that decay. With --multiple-kpi-splits the output is about 100 times larger.
  • --kaon-pion-lifetime-factor in run_fixedTarget.py scales the Geant4 lifetimes of charged kaons and pions, for validating the kaon/pion splitting: with short lifetimes, decays in flight are common enough to compare split and unsplit samples decay by decay with few events. Geant4's decay and the per-step splitting both use the scaled lifetime. Samples made with a factor other than 1 are not physical; the factor is recorded in the FileSummary.
  • Record split sets for kaon/pion splitting. ShipMCTrack (class version 10) gains GetSplitSet(), GetSplitRole() and GetSplitWeight(): all tracks created for one split kaon or pion share a split set, the track and its continuations as the survivor line (kSplitSurvivor) and the clones as decay alternatives (kSplitDecay), and the split weight is the track's weight before splitting. Clones and continuations are pushed with the split track's mother, so before this they could not be told apart from real siblings. Files written earlier read back as not split. python/split_provenance.py uses the split sets to tell whether two tracks can exist in the same event, to weight pairs of tracks, and to de-split an event into one analog-like realisation for multiplicities, coincidences and occupancy.
  • Add field/canonicaliseFieldMap.py to rewrite an existing ROOT field map in the ordering ShipBFieldMap expects, working the input ordering out from the stored coordinates and from the divergence of the field, and field/plotFieldMap.py to draw the components of a map straight from the file, optionally showing the same file read both ways. tests/test_field_maps.py applies the same checks to every map in files/, and the python tests now run under ctest alongside the C++ ones.
  • UBT digitization: each UpstreamTaggerHit is placed at the center of the fired 20 x 20 or 40 x 40 mm2 tile and carries a tile ID, ADC counts from position-dependent response maps (TH2D adc_per_mev_{20,40}mm in geometry/UpstreamTagger_adc_response.root) and a trigger flag (ADCTriggerThreshold). There is one hit per fired tile: the ADC signals of all MC points in a tile (e.g. a muon and a delta ray) are summed before the trigger threshold is applied, the hit time is that of the first point, and the new digiUBT2MC branch lists the MC points of each hit, with their unrounded ADC signals in digiUBT2MCADC
  • UpstreamTaggerScoringPlane: two 1 mm thick vacuum scoring planes. Plane 1 (4.4 x 6.728 m2, centred on the beam axis, y in [-3.364, 3.364] m, from the ECN3 floor) sits on the decay vessel entrance and stores every track entering it. Plane 2 (9.132 x 8.564 m2, x in [-4.566, 4.566] m, from the ECN3 side wall to its mirror image, and y in [-3.364, 5.2] m, from the ECN3 floor) sits 10 cm downstream of the muon shield and stores only muons. Each entering track is stored as an UpstreamTaggerScoringPoint (new UpstreamTaggerScoringPoint branch, detID = plane number), independent of energy deposit. As for CaloScoringPlanePoint, scoring points alone do not keep an event in --MuonBack mode. Plane 1 does not keep the tracks of its points in MCTrack (AddPlane(..., keepTracks) of SHiP::ScoringPlane, KeepTracks in the geometry configuration), so with MCTracksWithHitsOnly the soft secondaries it sees are not all kept; their points get track ID -2
  • Add --pythia8-tune (default, FTFT) to run_fixedTarget.py and FixedTargetGenerator::SetPythiaTune to select the FTFT Pythia8 tune for open charm and beauty production in fixed-target collisions (arXiv:2608.29076) in the Pythia8 primary interaction. The Pythia8 default (Monash 2013) remains the default. Charm and beauty read from cascade input files are unaffected. SetPythiaTune takes the same tune names as the command line, with default and the empty string both selecting the Pythia8 default. run_fixedTarget.py rejects the flag up front when combined with --charm, --beauty or --G4only, where the tune would have no effect. A non-default tune also tags the work directory (e.g. <host>_run_fixedTarget_1_FTFT), so runs that differ only by tune no longer overwrite each other.
  • Add macro/makeCascadePythia8.py, a Pythia8 version of makeCascade.py that writes charm or beauty cascade files in the same format, with --pythia8-tune (default, FTFT). With FTFT, charm is normalised to the tune's inclusive charm cross section through forced-production K-factors that depend on the beam particle, the target nucleon and the momentum; beauty uses the tune's K-factors. Elastic scattering does not increase the cascade depth, so the depth-1 normalisation used by run_fixedTarget.py covers the beam proton up to its first inelastic interaction and its elastic re-interactions are not counted twice. makeCascade.py is unchanged. FixedTargetGenerator tags hadrons from depth 1 as primary when the input file has the depth branch, so beam protons that scattered elastically before are included; files without it keep the zero-transverse-momentum test.
  • Add --charm-production (forced, inclusive) to macro/makeCascadePythia8.py. With inclusive, charm signal events are inclusive inelastic events (SoftQCD:inelastic) generated at the exact momentum and direction of the projectile and kept if they contain charm, as in the FTFT tune, instead of forced HardQCD:hardccbar events. The normalisation is unchanged. Inclusive generation is about 20 times slower; forced remains the default.
  • Add the V21_2455 spectrometer field map (files/2026_07_02_MainSpectrometerField_V21_2455.root). The map was delivered with its x and y coordinate columns transposed, like the 2026_05_07_* maps, and is shipped with the coordinates regenerated. The field values are unchanged.
  • Add CaloScoringPlane detector: an ideal thin vacuum plane at the ECAL front face (z = 97.17 m, integration layout 2026-0.1) (ship_geo.CaloScoringPlane). Every track entering it is stored as a CaloScoringPlanePoint (MC-truth position, momentum, time and PDG code at the exit face), without an energy-deposit requirement. Secondaries are only kept in MCTrack because of these points if the stack is configured with a minimum number of points; otherwise such points carry track ID -2.
  • Add --cascade-model (nucleus, nucleon) to macro/makeCascadePythia8.py. With nucleus, the default, every interaction of a cascade hadron is a hadron-nucleus collision built from hadron-nucleon subcollisions as in Pythia's PythiaCascade, with the heavy-flavour probability per hadron-nucleus collision, A sigma(signal)/sigma(hA). This matches the normalisation of run_fixedTarget.py, which is per proton-nucleus interaction and already contains the subcollisions inside the nucleus; single collisions on free nucleons (nucleon, as in makeCascade.py) count them twice and overestimate the cascade. The tables of the average number of subcollisions and the process of the later subcollisions follow the installed Pythia version (8.312 to 8.316, or 8.317 and later), and hadrons decay only once the collision is complete, so that a leading resonance collides again itself, as in PythiaCascade.
  • --intermediate-kaon-pion-splits (default 2): splitting factor applied to kaons and pions at each GEANT4 step before they decay, separate from the --kaon-pion-splits factor applied at the decay itself
  • --max-split-buffer (default 25000): hard bound on the split clones buffered per track. Per-step splitting stops once the cap is reached, reducing the statistical boost but conserving weight. With the default --max-event-size, that cap is reached first, at about 10k pending clones
  • --max-event-size (default 5000000): cap on the projected number of particles per event, counting the particles already on the stack plus 500 for each pending split clone. Per-step splitting stops once the cap would be exceeded; weight is conserved. run_fixedTarget.py rejects values of this or --max-split-buffer that are too small for even one per-step split
  • exitHadronAbsorber reports the split-clone balance (decays split, clones created, clones never tracked and their weight) at the end of the run, including the final event's leftover buffer
  • ACTS is available as an alternative track fitter in the main reconstruction chain: ShipReco.py --trackFitter acts writes RecoTracks/RecoVertices/Particles branches instead of the GenFit FitTracks (which remains the default). Both fitters write goodTracks, and one VetoHitOnTrack entry per good track with the distance in cm. Analysis tools (ShipAna, shipVeto, analysis_toolkit, tracking_benchmark) detect either output format automatically. The fitter is the new ActsTracking library (SHiP::ActsStrawTracker), which is built against upstream ACTS (acts-core 48) when CMake finds it. It builds the straw surfaces from the loaded geometry and uses the same magnetic field as the simulation. The tracks and vertices are stored as SHiP::RecoTrack and SHiP::RecoVertex in shipdata, so reco files can be read without ACTS. The fit resolves the left/right ambiguity of the straw hits itself and drops hits that do not fit the track. Vertices are fitted for every opposite-charge pair of good tracks, as in the GenFit vertexing, by iterating the closest approach of the tracks extrapolated through the field. The ShipParticle four-momenta take the daughters to be muons.
  • New --patRec Truth option for MC-truth hit assignment (requires --trackFitter acts). Only the assignment of hits to tracks comes from the truth; the fit starts from the hits alone.
  • New --patRec Segments option (requires --trackFitter acts): pattern recognition from the drift circles of the hits, with straight segments before and after the magnet matched across it, in the ActsTracking library (SHiP::StrawPatRec). On common-vertex muon events it finds 99.3 ± 0.1% of the tracks for 2 tracks per event, 92.9 ± 0.2% for 8 and 72.5 ± 0.3% for 20, with ghost rates below 1%. GenFit with AR finds 96.7 ± 0.2%, 72.2 ± 0.4% and 2.2 ± 0.1%, with ghost rates of 1.8%, 18.9% and 80%. On HNL decays, both find 97% of the daughters, and GenFit still has the better momentum (1.01 vs 1.08%) and vertex resolution.
  • --commonVertex for the particle gun with --multiplePG gives all particles of an event the same vertex, and --smearMode uniform3d --Dz spreads the vertex along z, for multi-track events from vertices in the decay volume.
  • The tracking benchmark reports vertexing (vertex and pair efficiency, fake rate, vertex resolution, DOCA and pair mass resolution, with statistical uncertainties on the widths) and the tracking rates per event multiplicity. run_tracking_benchmark.py gains --trackFitter, --patRec, --commonVertex, --Dz, --allTracks (secondaries are reconstructible), --strawPurity (a hit belongs to every track crossing its straw) and --skipSim/--skipReco.
  • Add scoring-plane digitisation with electron / hadron / muon identification. CaloScoringPlaneDetector writes one CaloScoringPlaneHit per forward-going, non-neutrino CaloScoringPlanePoint to Digi_CaloScoringPlaneHits (MC link in digiCaloScoringPlane2MC), carrying the species drawn by the new C++ class CaloScoringPlanePID (usable from C++ and Python) from energy-dependent 3x3 confusion matrices, read from a YAML file (in Python, python/caloScoringPlanePID.py) and interpolated at the particle energy. Select the file with ShipReco.py --caloScoringPlanePID; default is perfect identification. See CaloScoringPlane/README.md and geometry/caloScoringPlane_pid_provided.yaml.

Changed

  • CaloScoringPlane now shares SHiP::ScoringPlane (Detector/ScoringPlane.h) with the new UpstreamTaggerScoringPlane: thin vacuum planes that record every track entering them, with the values at the end of the track's first step in the plane, several planes per detector and an optional filter on absolute PDG codes per plane. The CaloScoringPlane interface, its points, volume and node are unchanged
  • run_fixedTarget.py simulates the field of the hadron absorber and the muon shield by default (--AddMuonShieldField is now on; --no-AddMuonShieldField turns it off). run_simScript.py --MuonBack now continues the scored tracks from the scoring plane (see Fixed), so the field up to the plane has to be part of the first stage. This also applies to ci-fixed-target.
  • ShipUnit.h keeps only the units the C++ code uses and defines them as constexpr: lengths (cm = 1), times (ns = 1), energies (GeV = 1, as in shipunit.py and VMC; it was MeV = 1), magnetic fields (kilogauss = 1) and the speed of light. The other CLHEP units, the angles and the physical constants are gone; use TMath for constants.
  • The FTFT Pythia8 tune is defined once, in gconfig/FTFT.cmnd, and read from there by FixedTargetGenerator and makeCascadePythia8.py, which each kept their own copy before. The settings are unchanged.
  • -g of run_simScript.py now gives a geometry file to simulate on (see Added). It used to set ship_geo.muShieldGeo, a muon shield geometry file that nothing has read since the muon shield stopped being built from files; muShieldGeo is removed from geometry_config.create_config.
  • Follow the integration layout EDMS 3287817 v1.1 (WMS 2026-0.1, drawing SPSXXSHIP0002) for the positions along the beam. The gap between the M1 and M2 yokes of TRY_2026 is 0.3 m instead of 0.15 m, so M2 to M7 move 0.15 m downstream; the spectrometer magnet mid-plane is at 89.72 m (was 89.57 m), which moves the decay vessel, UBT, tracker stations, timing detector and calorimeter by the same 0.15 m; the front face of the timing detector is at 96.14 m, and the CaloScoringPlane is at the ECAL front face, 97.17 m, instead of 0.561 m behind the timing detector. The scattering detector moves one magnet upstream: with --SND, the SiliconTarget now ends at the downstream face of S5 and the MTC is centred in M6, and the hole in the shield is cut in those two magnets (ShipMuonShield::SetSNDSpace takes the magnet indices). The muon-shield field map files/TRY_2026.root is regenerated for the 0.3 m gap, so the field of M2 to M7 moves downstream with the iron. The field of the hadron stopper and M1 is unchanged, and that of M2 to M7 was recomputed, which changes it by up to about 2% per magnet. The map now extends to 32 m behind the hadron stopper entrance instead of 30.75 m.
  • The default spectrometer field map is now files/2026_07_02_MainSpectrometerField_V21_2455.root. Its polarity is opposite to the MgB2 map it replaces: the integral of Bx along the beam axis is +0.84 T m, against -0.83 T m before, so charged tracks bend the other way in y. Off axis the bending power differs too, so samples produced with the earlier default are not comparable, and a sample has to be reconstructed with the map it was simulated with. The MgB2 map remains available through --field_map.
  • Update default He balloon liner to be made with polyester like Mylar, named mylar_linerHe with density/thickness matching material #5
  • Scale chicc/chibb in run_fixedTarget.py by the heavy-flavour cross section per nucleon stored in the cascade input file, so that the normalisation follows the beam energy, tune and target composition the file was generated with. Files without it, such as the existing ones on EOS, keep the previous values.
  • Default for reweighting boosted muon files is now to keep all events rather than only those containing a muon
  • The UBT is now a 3.4 x 5.04 m2 (x in [-1.7, 1.7] m, y in [-3.34, 1.7] m, from just above the ECN3 floor to above the decay vessel entrance) polystyrene scintillator plane (Scintillator medium) split into regions generated on the UBT box from the rule in geometry/UpstreamTagger_config.yaml, so that they follow the box when the cavern, Top or FloorMargin change (5 mm thick for 20 mm tiles, 10 mm for 40 mm tiles) and no longer a vacuum scoring box. The UBT map is stored with the geometry (UpstreamTagger_geo), and reconstruction, analysis and -g use the stored map instead of the YAML file of the checkout, with a warning when they differ
  • The UBT position and size and the scoring planes are derived from the decay vessel entrance (decayVolume.z0), the muon shield end and the ECN3 cavern instead of hardcoded values. The UBT position is now UpstreamTagger.z (centre) and UpstreamTagger.z0 (front face) instead of UpstreamTagger.Z_Position, which is removed. Geometry files written before this change can still be used for reconstruction and analysis: shipDet_conf.configure fills in the ECN3 cavern defaults and replaces their UBT vacuum box by the current UBT and scoring planes, placed from the stored decay vessel and muon shield, but their UBT points, which carry the detector IDs of the old box, are not digitized (with a warning). They cannot be used with -g, since the old UBT can no longer be built
  • The UBT veto (shipVeto.UBT_decision, used by ShipAna.py) counts the triggered tiles in Digi_UpstreamTaggerHits instead of the UpstreamTaggerPoints above 100 MeV/c, with an efficiency of 0.999 per tile instead of 0.9 per point. The mcParticle selection uses the MC points of each tile (digiUBT2MC). A reconstruction without UBT digits (geometries from before the scintillator UBT) gives no UBT veto
  • UBT points of secondaries created in the plastic (delta rays, Compton electrons) no longer keep their tracks in MCTrack, so with MCTracksWithHitsOnly (--MuonBack) the soft electrons of every crossing muon are not all kept; their points get track ID -2 unless the track is kept for another reason. The points themselves and the digitization are unchanged
  • UBT regions of the same shape share one volume (3 instead of 442 for the default box), placed with the region ID as copy number, so the detector IDs are unchanged. The volumes are named UpstreamTaggerRegion_<tile size>cm_<n>; digitization reads the tile size of each region from the placed nodes and still accepts geometry files with one volume per region
  • --multiple-kpi-splits now splits with --intermediate-kaon-pion-splits at each step instead of reusing --kaon-pion-splits, and requires both to be positive
  • Kaon/pion splitting takes the clone weights from the current weight of the split track, instead of assuming that the track has the same weight as its mother on the stack, or weight 1 if it has none. That holds for all current inputs, so results do not change
  • Make muon shield field uses field map (rather than set it to uniform) when --AddMuonShieldField is set to true in run_fixedTarget.py

Fixed

  • run_simScript.py --MuonBack with run_fixedTarget.py input continues each scored track from where it crossed the scoring plane, instead of replaying it from its production vertex. The replay counted the probability of reaching the plane twice, and FollowAllParticles() had the same problem. The origin entry stays in the output, untracked, as the mother of the tracked plane copy (kPTransportation), so weight sums over MCTrack have to skip one of the two. --SmearBeam/--PaintBeam are no longer applied a second time, --phiRandom is refused, and input simulated without the absorber field is refused unless --MuonBackAllowNoAbsorberField is given. --MuonBackFromOrigin restores the old behaviour.
  • run_simScript.py no longer stops with KeyError: 'PoT' after a simulation whose input has a FileSummary without PoT, EnergyCut or prodSite, as the output of run_fixedTarget.py has. Such a summary is now skipped with a warning when the output's FileSummary is written.
  • Simulations started through pixi no longer abort when there is no display, as over ssh, in a container or on a batch node. Geant4's Qt interface failed to find a display and aborted the run; activate.sh now sets QT_QPA_PLATFORM=offscreen when neither DISPLAY nor WAYLAND_DISPLAY is set, unless QT_QPA_PLATFORM is already set (#1223).
  • Geant4 is now found when building against the 26.02 CVMFS release. Its CMake (3.26) ignores the XERCESC_ROOT set by alienv and picked the system XercesC 3.2.5, which Geant4 11.4 rejects. The build has failed there since ShipMuonShieldBackground started linking Geant4VMC. CMake now sets XercesC_ROOT from XERCESC_ROOT when the former is not given.
  • The vectors stored in the reconstruction tree now have compiled ROOT dictionaries: FitTracks (std::vector<genfit::Track*>), digiSBT2MC (std::vector<std::vector<int>>), Particles and the digitised hits and tracklets of strawtubes, veto, TimeDet, UpstreamTagger, MTC and silicon target. Without them ROOT has Cling generate their destructors at run time. With ROOT 6.40, a script that read the reconstruction tree and had created an object of a new template type from Python (e.g. genfit::SharedPlanePtr) segfaulted at exit, when ROOT deleted these branches. Files written before can still be read.
  • run_fixedTarget.py -C/-B stops with an error when FixedTargetGenerator::InitForCharmOrBeauty rejects the input file, for example one without the POT histogram 2. The return value was ignored, so the run went on with no input tree and segfaulted on the first event.
  • The pixi environment sets EOSSHIP to root://eospublic.cern.ch/ unless it is already set, as the aliBuild environment did. Without it, run_simScript.py with its default configuration failed to open the charm cascade input (OSError: Failed to open file $EOSSHIP/eos/...), and so did the other defaults read from /eos/experiment/ship.
  • TrackExtrapolateTool.extrapolateToPlane extrapolates again (#671). It called GENFIT with two TVector3, which no overload accepts, and caught the TypeError, so it never extrapolated: the event display drew fitted tracks as straight lines and ShipAna's extrapTimeDetX/Y stayed empty. It now also takes the charge from the fit instead of from the sign of the seed's PDG code, which bent tracks whose charge the fit had flipped the wrong way in the spectrometer magnet.
  • tracking_benchmark.py skips track points without fitter info instead of stopping. TrackPoint::getFitterInfo returns a null pointer for such a point, which PyROOT gives as an object that is falsy but not None, so the is None check never skipped it and getResidual() raised ReferenceError, which the except clause does not catch: run_tracking_benchmark.py aborted in its metrics phase once a sample contained such a point. On linux-aarch64 that happened already with CI's settings (-n 200 --seed 42) and with -n 1000; CI's linux-64 runs have not hit it so far.
  • HNL decay channels with a self-conjugate daughter (pi0, eta, rho0, omega, eta', phi, eta_c) no longer abort the simulation. readDecayTable.addHNLdecayChannels adds every enabled channel a second time, charge conjugated, and keeps a daughter's code when TDatabasePDG has no antiparticle for it. Since 26.03 that lookup was tested with is not None, which is always true, because PyROOT returns a null pointer (falsy, but not None) for an unknown code. The conjugate channel therefore carried codes such as -111, which Pythia8 accepts and Geant4 rejects, ending the run at the first such decay. The default channel, N -> pi+ mu-, was not affected.
  • The checks for unknown PDG codes added in 26.06 (assert p is not None, "Unknown PDG: ...") could never fire, so an unknown code still ended in ReferenceError: attempt to access a null-pointer. They now use rootUtils.get_particle, which raises ValueError with the code. For the same reason DrawCharmTracks in the event display and the charge check in tracking_benchmark.py now skip particles with unknown codes instead of failing, and configGenieGenerator.py reports a missing volNuTauMudet_1 as intended.
  • Test pointers returned from C++ for truthiness instead of comparing them with None. PyROOT returns a null pointer as a falsy proxy, never as None, so the guards in ana_ShipMuon.py (missing FAIRGeom) and compare_histograms.py (key of an unknown class, which raised a TypeError) never triggered.
  • FairShip built from a GitHub tarball, as the conda package is, has its real version instead of 0.0.0. CMake reads the tag and commit from .git_archival.txt, which git archive fills in, when there is no .git.
  • ShipGeo in a geometry file records the versions of the run that wrote it: FairShip (the Python source), the new FairShipLibrary (the compiled libraries, from the newly installed FairShipVersion.h, which is regenerated on every build and marks a commit with uncommitted changes as -dirty) and FairRoot (from FairVersion.h when FAIRROOT_HASH is not set). A version that cannot be determined is left out rather than kept from a configuration loaded with -g. geometryBuiltWithFairShip is unknown if the geometry file has no FairShip version, so a later -g run no longer records its own version as the builder.
  • exitHadronAbsorber writes the momentum spectra of charged pions, kaons and protons. They were booked and filled but never written, because booking and writing used two copies of the particle table that had drifted apart, and the spectra of negative pions and kaons and of antiprotons were not booked at all. Booking and writing now share one table, with both charges for pions, kaons and protons.
  • Pythia8Generator counts the material for interactions further down a charm cascade from the previous interaction point instead of from the start of the target. The distribution of interaction points is unchanged, but the acceptance no longer drops with every step, which could make deep cascades loop practically forever. The loop is now also bounded.
  • FixedTargetGenerator takes the end of the target from the last slab when the target is found by volume name. It looked up the last slab at the capacity of the node array and used the half-length of the first slab.
  • The magnetised hadron stopper and M1 start at 2.14 m and 4.59 m as in the integration layout; the 10 cm that geometry_config.py subtracted from the hadron absorber position is gone.
  • The TCC8 floor ends at 21.37 m instead of 20.52 m, so that the 0.82 m stair step down to ECN3 is centred on the gap between M4 and S5. The spectrometer yoke pit is centred on z from geometry_config.py, passed through the new ShipCave::SetSpectrometerZ, instead of on a hard-coded 89.57 m.

  • Per-step kaon/pion splitting now lowers the weight of the parent kaon or pion as weight is split off into clones. The survival factor was only kept internally before, so a parent that ended by interacting rather than decaying still contributed its own hit at the sensitive plane, and the secondaries of that interaction, at full weight. Only --multiple-kpi-splits runs are affected; with --kaon-pion-splits alone no weight is split off before the decay
  • Split clones are no longer subject to the transport energy cut. A clone is the parent re-injected at its decay point, so re-applying the cut there discarded clone sets that an unsplit run keeps
  • The products of a kaon or pion decay that the split clones re-sample are no longer transported. Only their direct crossings of the scoring plane were excluded before, so muons from their own decays and interactions (for example K → π → μ) were counted on top of the same chains from the clones, an excess of relative size ~λ_int/λ_decay that grows when kaon or pion lifetimes are scaled down
  • Per-step kaon/pion splitting (--multiple-kpi-splits) no longer applies the decay probability twice.
